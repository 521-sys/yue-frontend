# 本地视频自动生成台词：设计

日期：2026-10-10

## 目标与范围

在现有“电影模仿”网页中，用户导入本地视频后点击“自动生成台词”，网页把该视频交给**同一台电脑**上的语音识别服务处理，随后把带起止时间的台词填进现有可编辑时间轴。成功标准是用户能对有声短片完成“导入视频 → 点击识别 → 查看/校对台词 → 点击台词定位 → 逐句录音”，不再需要手工准备 SRT。

这是个人本地测试版。视频不发送到云端，模型离线运行；但视频会从浏览器上传到本机 HTTP 服务，并在处理期间存成临时文件。第一版不处理背景音分离、导出成片、工程持久化或多人使用。无可识别人声的视频可以返回零句；模型对粤语可能有错字和时间边界误差，结果必须可校对。

## 方案选择

采用独立的 Python 本地识别服务，复用已经在这台电脑上验证过的 `faster-whisper` small 模型。纯浏览器运行模型会增加模型下载、内存和兼容性负担；云端识别会引入上传、费用与用户数据保护要求。这两个方向都不在本轮实现。

服务放在 `yue-backend/media-worker`，以 FastAPI/Uvicorn 提供本地接口，和现有 FFmpeg 渲染核心并列，不修改 Java 后端。它仅监听 `127.0.0.1`，默认端口为 `8765`，可通过环境变量修改。网页直接请求此本机地址，不经过会对局域网开放的 Vite 代理。服务只接受本机网页 Origin（开发时 `http://localhost:8443` 和 `http://127.0.0.1:8443`），拒绝其他 Origin，并为这两个 Origin 提供跨域预检响应；这只是本地隔离措施，不是生产鉴权。不得将此服务绑定到 `0.0.0.0` 或直接部署公网。

## 组件与数据流

1. 网页保留所选视频的 `File` 引用，当前已有的 Blob URL 继续只供播放器预览。用户点击“自动生成台词”时，网页向本地服务发送一次 multipart 请求。仅导入视频不会触发上传或识别。
2. 本地服务先检查文件大小和类型，再把上传内容流式写入临时文件；超限、缺少音轨、无法解码或模型不存在时返回明确错误。启动时必须设置 `ASR_MODEL_DIR` 指向已下载模型（当前测试可用 `.asr-probe/models/small`）；运行时不自动联网下载模型。
3. 服务调用 `faster-whisper`，固定中文识别、启用 VAD，返回按开始时间排列的非空句段。每句为 `{startMs, endMs, text}`；时间是整数毫秒，满足 `0 <= startMs < endMs`。第一版保留模型原始句级分段，不承诺精准逐字对齐，也不自动合并/拆分句子。
4. 网页把成功结果映射为现有 `DubbingCue`，供校对、定位、录音、删除和 SRT 导出。模型返回零句时显示“未识别到台词，请确认视频有人声，或手动新增/导入 SRT”。
5. 服务无论成功或失败都清理临时上传文件；网页不把视频或识别内容写入持久存储。页面刷新后仍需重新导入，这是现有项目限制。

## 接口与限制

`POST /transcribe`：multipart 字段 `file` 为当前视频。成功响应 `200`：`{"cues":[{"startMs":44880,"endMs":46200,"text":"……"}]}`；无语音时 `cues` 为空。错误使用 `{"error":"可读的原因"}`，区分无文件/无效请求（400）、体积超限（413）、无法解码或无音轨（422）、模型不可用（503）和处理失败（500）。提供 `GET /health` 返回服务与模型可用状态，供页面给出“本地识别服务未启动”的提示。

个人测试版限定视频最长 5 分钟、文件不超过 200 MB；超限时不处理并提示用户截取片段。服务一次只处理一个请求，避免并发占满 CPU。实际 CPU 耗时随视频和机器变化，网页只显示“正在识别”，不伪造百分比进度。

Python 依赖应固定兼容版本，包括 `av<19`（当前已验证的环境中，新版 PyAV 与 `faster-whisper` 的解码调用不兼容）。README 提供本机启动、模型路径与故障排查步骤，不要求额外 CUDA；本轮 CPU 是默认路径。

## 网页交互与状态保护

按钮只在已导入可播放视频且没有正在录音时可点；识别期间禁用重复提交。按钮旁说明“仅点击后发送至本机识别服务”。网页请求失败时保留原有台词与录音，并显示具体错误。

如果已有台词或录音，点击识别前先确认“新结果将替换当前台词及对应录音”；取消则不上传。识别成功且有台词后才替换旧时间轴、清理旧录音 URL，并选中第一句。零句结果不清除已有内容。导入新视频、离开页面或请求过期后，旧请求的迟到结果不得覆盖当前视频的台词。浏览器取消请求不保证已开始的本机 CPU 计算立即停止，界面不宣称具备服务端取消功能。

现有“导入 SRT”“新增台词”“导出 SRT”继续保留，作为纠错和识别失败时的后备路径。

## 验证

- 后端单元测试用可替换的识别器模拟成功、零句、解码失败和缺少模型，不在普通测试中下载或运行大模型；接口测试覆盖请求验证、大小上限、Origin 限制和临时文件清理。
- 前端测试覆盖按钮状态、显式点击才上传、识别成功后生成台词、已有录音的替换确认、失败/零句不清空原内容、切换视频后忽略旧响应。
- 本机手动验收使用已有有声视频，检查台词出现在正确大致时间并可校对；再用无语音的 12 秒视频检查零句提示。记录模型错字和边界误差，不把识别初稿当作准确字幕。

## 上线边界

此设计不等于多用户线上部署。上线前要把本地端点改为受鉴权保护的服务端异步任务，并增加用户隔离、上传授权、存储与到期删除、资源配额、监控和费用控制；不能把本地 HTTP 服务直接对公网开放。
