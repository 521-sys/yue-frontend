> 技术栈：React 19 + Vite 8 + TypeScript + Tailwind v4
> 文档目的：阐述本项目所有数据的存储方案、数据结构与相互关系

## 1. 存储方案概述

本项目是**纯前端无后端**应用，不存在传统意义上的服务端数据库。所有持久化数据均存储在浏览器本地存储 `localStorage` 中。

| 项目 | 说明 |
| --- | --- |
| 存储介质 | 浏览器 `localStorage`（同步 API） |
| 存储键名 | `yueLearnReactV1` |
| 存储值格式 | JSON 字符串 |
| 存储内容 | `LearningState` 对象（用户学习进度） |
| 生命周期 | 与浏览器/域名绑定，用户清除浏览数据时丢失 |
| 容量上限 | 约 5MB（浏览器实现差异） |
| 读取时机 | 应用启动时 `load()` 调用一次，缓存到内存 |
| 写入时机 | 每次调用 `save()`（即每次状态变更） |
| 兜底策略 | 解析失败或读取异常时回退到 `DEFAULT` 默认值 |

> ⚠️ 注意：词表、词典、音频清单为**静态数据**，直接打包到 JS Bundle 中，**不存储在 localStorage**。localStorage 只承载用户个人学习进度。

### 1.1 存储键定义

```ts
// src/lib/store.ts
const KEY = "yueLearnReactV1";
```

键名命名规则：
- `yue`：项目代号（粤语学习）
- `Learn`：业务域（学习）
- `React`：技术栈标记（与历史小程序/H5 版本区分）
- `V1`：数据版本号（用于未来数据迁移）

### 1.2 读写流程

```
启动 → load()
         ├─ localStorage.getItem(KEY)
         ├─ 解析 JSON.parse(raw)
         ├─ { ...DEFAULT, ...parsed }  // 字段合并兜底
         └─ 异常返回 { ...DEFAULT }

运行时 → 调用 markLearned/markStuck/markReviewed/buyItem/removeStuck/setDailyGoal/resetAll
         → save(next)
            ├─ state = next
            ├─ localStorage.setItem(KEY, JSON.stringify(next))
            └─ listeners.forEach((l) => l())  // 通知 React 订阅者
```

```ts
// src/lib/store.ts
function load(): LearningState {
  try {
    const raw = localStorage.getItem(KEY);
    if (!raw) return { ...DEFAULT };
    return { ...DEFAULT, ...JSON.parse(raw) };
  } catch {
    return { ...DEFAULT };
  }
}

let state: LearningState = load();

function save(next: LearningState) {
  state = next;
  try {
    localStorage.setItem(KEY, JSON.stringify(next));
  } catch {
    /* ignore */
  }
  listeners.forEach((l) => l());
}
```

## 2. LearningState 数据结构表

`LearningState` 是 localStorage 中唯一持久化的对象结构，承载用户的全部学习进度、激励数据与资产。

```ts
// src/lib/store.ts
export interface LearningState {
  learned: string[]; // 已「记」（斩）的词 id
  stuck: string[]; // 生词本（选错 / 再背一次）
  reviewed: string[]; // 已「背」过的词 id
  streak: number; // 连续学习天数
  lastDay: string; // 最后学习日期
  todayLearned: number; // 今日已记数量
  todayLearnedDate: string;
  todayReviewed: number; // 今日已背数量
  todayReviewedDate: string;
  dailyGoal: number; // 每日目标（词）
  activity: Record<string, number>; // date -> 当天学习动作数
  coins: number; // 铜板余额
  owned: string[]; // 已购商品名
}
```

### 2.1 字段逐项说明

| 字段名 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `learned` | `string[]` | `[]` | 已「记」（斩对）的词 id 列表。词 id 形如 `w1`、`w2`…，参见 [§3.2 Word 接口](#32-word-接口字段表)。去重逻辑由 `markLearned` 保证（追加前判断 `includes`）。 |
| `stuck` | `string[]` | `[]` | 生词本中的词 id 列表。「记粤语」选错、「背粤语」选「再背一次」时进入；`removeStuck` 可移出。 |
| `reviewed` | `string[]` | `[]` | 已「背」过的词 id 列表。`markReviewed` 时追加（去重）。 |
| `streak` | `number` | `0` | 连续学习天数。跨日时若 `lastDay` 为昨天则 +1，否则重置为 1。 |
| `lastDay` | `string` | `""` | 最后一次产生学习动作的日期，格式 `YYYY-MM-DD`（UTC，来自 `new Date().toISOString().slice(0,10)`）。 |
| `todayLearned` | `number` | `0` | 今日已「记」的词数，跨日重置为 0。配合 `todayLearnedDate` 判断是否同一天。 |
| `todayLearnedDate` | `string` | `""` | `todayLearned` 所属日期 `YYYY-MM-DD`，用于跨日重置判断。 |
| `todayReviewed` | `number` | `0` | 今日已「背」的词数，跨日重置为 0。配合 `todayReviewedDate`。 |
| `todayReviewedDate` | `string` | `""` | `todayReviewed` 所属日期 `YYYY-MM-DD`。 |
| `dailyGoal` | `number` | `10` | 每日学习目标词数。用户可在个人中心通过 `setDailyGoal` 调整。 |
| `activity` | `Record<string, number>` | `{}` | 学习活动日历。键为日期 `YYYY-MM-DD`，值为当天累计的学习动作数（每次 `markLearned`/`markStuck`/`markReviewed` 调用 `bumpActivity` 时 +1）。用于绘制「学习记录」中的近 7 天柱状图。 |
| `coins` | `number` | `128` | 铜板余额。初始赠送 128 枚；用于商城购买商品。`buyItem` 时扣减。 |
| `owned` | `string[]` | `[]` | 已购商品名列表（存的是商品 `name` 字符串而非 id）。`buyItem` 成功时追加。 |

### 2.2 默认值定义

```ts
// src/lib/store.ts
const DEFAULT: LearningState = {
  learned: [],
  stuck: [],
  reviewed: [],
  streak: 0,
  lastDay: "",
  todayLearned: 0,
  todayLearnedDate: "",
  todayReviewed: 0,
  todayReviewedDate: "",
  dailyGoal: 10,
  activity: {},
  coins: 128,
  owned: [],
};
```

### 2.3 跨日处理逻辑

```ts
// src/lib/store.ts
function today(): string {
  return new Date().toISOString().slice(0, 10); // UTC 日期
}

function touchStreak(s: LearningState): LearningState {
  const d = today();
  if (s.lastDay === d) return s;             // 同一天不更新
  const yest = new Date(Date.now() - 86400000).toISOString().slice(0, 10);
  // 上次是昨天：连续 +1；否则：中断，重置为 1
  return { ...s, streak: s.lastDay === yest ? s.streak + 1 : 1, lastDay: d };
}
```

### 2.4 学习活动计数逻辑

```ts
// src/lib/store.ts
function bumpActivity(s: LearningState): LearningState {
  const d = today();
  return { ...s, activity: { ...s.activity, [d]: (s.activity[d] || 0) + 1 } };
}
```

> 💡 `markLearned` / `markStuck` / `markReviewed` 在 `save` 之前都会先调用 `bumpActivity(touchStreak(state))`，因此任何学习动作都会：
> 1. 触发 `streak` 与 `lastDay` 的跨日更新；
> 2. 让今日 `activity[d]` 自增 1。

### 3.1 Category 接口字段表

```ts
export interface Category {

  icon: string;

```

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `id` | `string` | 分类唯一标识，如 `greet`、`eat`、`traffic`、`shop`、`num`、`daily`、`time`、`work`、`slang` |
| `name` | `string` | 分类中文名，用于 UI 展示 |
| `icon` | `string` | 分类 emoji 图标 |

### 3.2 Word 接口字段表

```ts
export interface Word {
  id: string;
  yue: string;   // 粤语词
  jyut: string;  // 粤拼
  man: string;   // 普通话释义
  cat: string;   // 分类 id
  example: string;    // 粤语例句
  exampleMan: string; // 例句翻译
}
```

| 字段名 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `id` | `string` | 词的唯一标识，由 `w` + 序号生成（`w1`、`w2`、…、`w71`） | `"w1"` |
| `yue` | `string` | 粤语词文本（繁体/粤语用字） | `"你好"` |
| `jyut` | `string` | 粤拼注音（数字调号格式） | `"nei5 hou2"` |
| `man` | `string` | 普通话释义，可含括号补充说明 | `"你好"` |
| `cat` | `string` | 所属分类 id（外键 → `Category.id`） | `"greet"` |
| `example` | `string` | 粤语例句 | `"你好，我係廣東人。"` |
| `exampleMan` | `string` | 例句普通话翻译 | `"你好，我是广东人。"` |

### 3.3 id 自动生成逻辑

`words.ts` 中的原始数据未显式声明 `id`，通过 `map` 自动赋值：

```ts
// src/data/words.ts
const raw: Omit<Word, "id">[] = [ /* ...词表数据... */ ];
export const WORDS: Word[] = raw.map((w, i) => ({ ...w, id: `w${i + 1}` }));
```

> ⚠️ **顺序敏感性**：`id` 由数组下标决定，若插入或删除词项会导致后续所有 `id` 偏移，从而让用户 `localStorage` 中的 `learned`/`stuck`/`reviewed` 失配。修改词表需走数据迁移流程（详见 [§8](#8-数据迁移与版本说明)）。

### 3.4 辅助函数

```ts
// src/data/words.ts
export function catOf(id: string): Category {
  return CATS.find((c) => c.id === id) ?? CATS[0];
}

export function shortMan(man: string): string {
  return String(man).split("（")[0].split("(")[0];
}

export function shuffle<T>(arr: T[]): T[] {
  const a = arr.slice();
  for (let i = a.length - 1; i > 0; i--) {
    const j = Math.floor(Math.random() * (i + 1));
    const t = a[i];
    a[i] = a[j];
    a[j] = t;
  }
  return a;
}
```

| 函数 | 用途 |
| --- | --- |
| `catOf(id)` | 根据分类 id 查 `Category`，未命中返回首个分类 `CATS[0]` |
| `shortMan(man)` | 截掉释义中括号补充说明（如「四（与「死」谐音…）」→「四」），用于答题选项 |
| `shuffle<T>(arr)` | Fisher–Yates 洗牌，返回新数组（不修改原数组），用于出题选项随机化 |

## 5. 词典数据结构（src/data/dictionary.ts）

### 5.1 WordMapEntry 三元组

词典每条数据为一个三元组（Tuple）：

```ts
export type WordMapEntry = [string, string, string];
// 索引 0: 普通话 (man)
// 索引 1: 粤语    (yue)
// 索引 2: 粤拼    (jyut)
```

| 字段 | 类型 | 说明 | 示例 |
| --- | --- | --- | --- |
| `[0]` 普通话 | `string` | 普通话文本（用于匹配输入） | `"早上好"` |
| `[1]` 粤语 | `string` | 粤语翻译结果 | `"早晨"` |
| `[2]` 粤拼 | `string` | 粤拼注音 | `"zou6 san4"` |

### 5.2 WORDMAP 数组

```ts
// src/data/dictionary.ts
const rawMap: WordMapEntry[] = [
  ["早上好", "早晨", "zou6 san4"],
  ["不用客气", "唔使客气", "m4 sai2 haak3 hei3"],
  // ... 共约 90 条
];

// 按普通话长度降序排序，保证贪心最长匹配正确性
export const WORDMAP: WordMapEntry[] = rawMap.sort((a, b) => b[0].length - a[0].length);
```

> ⚠️ **排序副作用**：`WORDMAP` 是 `rawMap.sort(...)` 的结果。`Array.prototype.sort` 会就地修改数组，因此 `rawMap` 本身也被排序。`translate` 算法依赖**最长前缀优先**才能正确处理「早上好」 vs 「早」的歧义，故词典初始化时按普通话长度降序是必须的。

### 5.3 Seg 分段结果接口

```ts
  yue: string;
  jyut: string;

```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `man` | `string` | 该段普通话原文（命中词时为整词；未命中时为单字） |
| `yue` | `string` | 该段粤语翻译 |
| `jyut` | `string` | 该段粤拼（未命中时为空串 `""`） |

## 7. 数据关系图

### 7.1 词与分类、词典、音频的关系

```
                  ┌──────────────────────┐
                  │  CATS (9 项)         │
                  │  id: greet/eat/...   │
                  └──────────┬───────────┘
                             │ 1
                             │
                             │ N
                  ┌──────────▼───────────┐
                  │  WORDS (71 项)        │
                  │  id: w1..w71          │
                  │  cat: Category.id (FK)│
                  │  yue / jyut / man    │
                  │  example / exampleMan│
                  └──┬─────────────┬──────┘
                     │             │
                     │ yue/example │ yue 也参与词典匹配
                     │ 查音频       │
                     ▼             ▼
        ┌────────────────────┐  ┌──────────────────────┐
        │ AUDIO_MANIFEST     │  │ WORDMAP (词典)        │
        │ key=yue/example    │  │ [man, yue, jyut]     │
        │ val=mp3 path       │  │ 用于 translate 算法   │
        └────────────────────┘  └──────────────────────┘
```

文字描述：
- **`CATS` 1 → N `WORDS`**：一个分类对应多个词，`Word.cat` 是外键，引用 `Category.id`。
- **`WORDS.yue` → `AUDIO_MANIFEST`**：词的粤语字段作为键，查询单词发音。
- **`WORDS.example` → `AUDIO_MANIFEST`**：例句也作为键，查询整句发音。
- **`WORDS.yue` ↔ `WORDMAP`**：词表与词典是**两套独立**的数据。`WORDS` 是「卡片式」学习内容；`WORDMAP` 是「翻译引擎」词典。两者通过粤语词文本有交集，但不互相引用。
- **`WORDS.man` → `WORDMAP[0]`**：词典的普通话字段用于「记粤语」答题的释义选项。

### 7.2 学习记录与词的关系

```
┌────────────────────────────────────────────────┐
│ localStorage[yueLearnReactV1]  →  LearningState│
└────────────────────────────────────────────────┘
                                            │
              ┌─────────────────────────────┼─────────────────────────┐
              │                             │                         │
              ▼                             ▼                         ▼
        ┌──────────┐                ┌──────────┐               ┌──────────┐
        │ learned  │                │  stuck   │               │ reviewed │
        │ string[] │                │ string[] │               │ string[] │
        │ of Word.id│               │ of Word.id│              │ of Word.id│
        └────┬─────┘                └────┬─────┘               └────┬─────┘
             │                           │                          │
             └───────────────┬───────────┴──────────────────────────┘
                             │ 全部以 Word.id (w1..w71) 作为外键
                             ▼
                    ┌──────────────────┐
                    │   WORDS[]        │
                    │   id: w1..w71    │
                    └──────────────────┘
```

文字描述：
- `LearningState.learned` / `stuck` / `reviewed` / `owned` 均为**字符串数组**。
- 前三者元素是 `Word.id`（形如 `w1`、`w2`…），即指向 `WORDS` 数组的外键。
- `owned` 元素是商品的 `name` 字符串（不是商品 id，详见 `ShopScreen` 中 `items` 数组）。
- `activity` 是日期 → 计数的映射，不直接引用 `Word`。

## 8. 数据迁移与版本说明

### 8.1 版本号策略

当前存储键名 `yueLearnReactV1` 中的 `V1` 即为数据版本号。

**升级流程**：
1. 在 `store.ts` 中修改 `KEY` 为 `yueLearnReactV2`、`yueLearnReactV3`…
2. 在 `load()` 中检测旧键存在时执行字段映射，写回新键并清理旧键。
3. 用户在新版应用首次启动时自动完成迁移。

### 8.2 字段向后兼容

`load()` 已采用 `{ ...DEFAULT, ...JSON.parse(raw) }` 合并策略：

```ts
// src/lib/store.ts
function load(): LearningState {
  try {
    const raw = localStorage.getItem(KEY);
    if (!raw) return { ...DEFAULT };
    return { ...DEFAULT, ...JSON.parse(raw) };
  } catch {
    return { ...DEFAULT };
  }
}
```

- **新增字段**：旧数据缺该字段时，自动取 `DEFAULT` 中的值 → 向后兼容。
- **删除字段**：旧数据多出的字段会保留在内存中，但下次 `save` 时被丢弃。
- **类型变更**：若旧数据的字段类型不兼容（如 `number` 变 `string`），需要显式迁移脚本。

### 8.3 词表 id 稳定性问题

⚠️ **重要风险**：`Word.id` 由数组下标生成（`w${i+1}`），因此：

- **新增词**：追加到 `raw` 末尾是安全的（不影响已有 id）。
- **插入词**：会导致后续所有 id 偏移，用户 `learned`/`stuck`/`reviewed` 中的 id 失配。
- **删除词**：同样导致 id 偏移。
- **重排词**：导致 id 与原词失配。

**推荐迁移实践**：
1. 维护一张「永久 id 表」，将 `id` 字段持久化到 `raw` 中，而非依赖下标。
2. 修改词表时新增字段不动旧字段，避免破坏现有引用。
3. 若必须调整顺序，提供 `V2 → V3` 迁移脚本，根据词文本重新映射 id。

### 8.4 异常处理

`load()` 与 `save()` 均包裹 `try/catch`：
- 读取失败（JSON 解析错误）→ 回退 `DEFAULT`。
- 写入失败（quota 超限、隐私模式）→ 静默忽略，内存状态仍更新，但刷新后丢失。

## 9. 容量与性能考量

### 9.1 localStorage 容量

| 项目 | 占用估算 |
| --- | --- |
| `learned` 71 项 × ~4 字节 | < 1 KB |
| `stuck`/`reviewed` 类似 | < 1 KB |
| `activity` 365 天 × ~30 字节 | ~11 KB |
| `owned` 数组 | < 1 KB |
| 其他标量字段 | < 1 KB |
| **LearningState 总计** | **< 15 KB** |

localStorage 上限通常为 5MB，本项目数据量远低于上限，**不存在容量风险**。

### 9.2 写入性能

`save()` 每次调用都会：
1. 全量序列化 `state` 为 JSON 字符串；
2. 全量写入 localStorage；
3. 通知所有订阅者。

对于本项目规模（单用户、低频操作），这种「写穿」策略完全可接受。如果未来扩展为高频操作（如自动同步），需要考虑：
- 节流写入（如 100ms debounce）；
- 增量更新而非全量覆盖。

### 9.3 读取性能

- 应用启动时 `load()` 仅执行一次 `localStorage.getItem` + `JSON.parse`。
- 运行时通过 `useSyncExternalStore` 订阅内存中的 `state`，**不重复读取 localStorage**，性能等同于内存访问。

### 9.4 静态数据 Bundle 体积

| 静态数据 | 估算体积 |
| --- | --- |
| `WORDS`（71 项 × 6 字段） | ~10 KB |
| `WORDMAP`（约 90 项） | ~5 KB |
| `AUDIO_MANIFEST`（208 项） | ~5 KB |
| **总计** | **~20 KB** |

静态数据直接打包进 JS，Gzip 后更小，无需懒加载。

### 9.5 并发安全

`store.ts` 采用单例模式：
- `state` 是模块级单例；
- `listeners` 是单例 `Set`；
- 所有 mutation 通过 `save()` 串行执行。

在浏览器单线程环境下，**不存在并发问题**。但 `useSyncExternalStore` 要求 `getState` 返回不可变快照，因此 `save()` 必须返回新对象（通过 `{ ...s, ... }` 展开），这一点在所有 mutation 函数中已严格遵守。
