## 一、测试策略

本项目为纯前端 React 应用，测试遵循**测试金字塔**分层策略：

```
        ▲
       / \
      /   \  系统测试（少量，验证关键集成路径）
     /─────\
    /       \  单元测试（大量，验证纯函数与状态机）
   /─────────\
```

- **单元测试**：聚焦数据层（dictionary / words）与业务层（store）的纯函数与状态机，输入输出可预测、无 DOM 依赖、执行快。
- **系统测试**：聚焦表现层集成行为，渲染根组件 `App`，验证底部 Tab 导航与页面切换的端到端流程。
- **不测**：第三方库（React/lucide）、Vite 构建、Tailwind 样式输出。

## 四、运行方式

### 4.1 运行全部测试（CI 一次性运行）

```bash
npm test
# 等价于：vitest run
```

### 4.2 监听模式（开发时持续运行）

```bash
npm run test:watch
# 等价于：vitest
```

### 4.3 运行单个测试文件

```bash
npx vitest run src/__tests__/store.test.ts
npx vitest run src/__tests__/App.system.test.tsx
```

### 4.4 查看覆盖率

```bash
npx vitest run --coverage
```

## 五、测试约定

1. **每个用例独立**：`beforeEach` 中 `localStorage.clear()` + `resetAll()`，保证状态干净。
2. **不修改源代码**：测试失败时优先调整测试代码与 mock，不改动 `src/` 下业务逻辑。
3. **时间相关用例用 `vi.useFakeTimers()`**：streak / todayLearned 跨日测试通过 `vi.setSystemTime()` 推进时间，`afterEach` 用 `vi.useRealTimers()` 恢复。
4. **断言可读性**：使用 `@testing-library/jest-dom` 提供的 `toBeInTheDocument()` / `toEqual()` 等语义断言。
5. **隔离 DOM 副作用**：speech.ts 的 `Audio.play()` 在 jsdom 下会抛 "Not implemented"，已用 try-catch 在源码中吞掉，测试无需额外 mock。

## 六、已知测试环境注意事项

| 问题 | 原因 | 应对 |
| --- | --- | --- |
| `localStorage.clear is not a function` | Node 22 内置 localStorage（undici）与 jsdom 冲突 | setup.ts 提供 Map 版 polyfill 兜底 |
| `--localstorage-file was provided without a valid path` 警告 | Node 22 启动参数残留 | 仅警告，不影响测试结果，可忽略 |
| `Not implemented: HTMLMediaElement's play() method` | jsdom 不实现音频播放 | speech.ts 已 try-catch 吞掉，测试通过 |
| `__dirname` in vitest.config.ts 警告 | Vite 8 native config loader 不支持 | 仅警告，功能正常 |
