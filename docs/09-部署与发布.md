# 09 - 部署与发布

> 文档版本：v1.0  
> 适用项目：yue-frontend / figma-make-app  
> 依据：`vite.config.ts` + `package.json` + `dist/` 产物结构 + `.figma/make/` 配置  
> 部署形态：**纯静态托管**，无服务端运行时

---

## 一、构建

### 1.1 构建命令

```bash
npm run build
```

等价于 `vite build`。构建产物输出到 `dist/`。

### 1.2 产物结构

```
dist/
├─ index.html              # 入口 HTML（注入了 site.json 配置）
├─ assets/
│   ├─ index-XXXXXX.js     # React 应用主包（含 React/组件/数据）
│   └─ index-XXXXXX.css   # Tailwind 生成的样式
├─ audio/                  # 88 条离线粤语音频（a0001~a0088.mp3）
└─ robots.txt              # 当 site.json robots.index=false 时生成（Disallow /）
```

> 音频文件不经过 bundling，由 Vite 从 `public/audio/` 静态复制到 `dist/audio/`。

### 1.3 构建模式与 sourcemap

来源：[vite.config.ts](file:///c:/Users/liu123/WorkBuddy/2026-09-01-20-12-50/yue-frontend/vite.config.ts)

| 模式 | sourcemap | minify | 触发 |
| --- | --- | --- | --- |
| `vite build`（默认） | 关闭 | 开启 | 生产发布 |
| `vite build --mode development` | inline | 关闭 | Figma Make 缓存预览构建 |

```ts
const emitSourcemaps = mode === 'development'
build: {
  sourcemap: emitSourcemaps ? 'inline' : false,
  minify: !emitSourcemaps,
}
```

### 1.4 预览构建产物

```bash
npm run preview
```

等价 `vite preview`，本地起服务器托管 `dist/`，默认端口 `8443`（可被 `PORT` 覆盖），`host: 0.0.0.0` 支持局域网验证。用于发布前最终检查。

## 二、环境变量

| 变量 | 作用 | 默认 | 示例 |
| --- | --- | --- | --- |
| `PORT` | dev / preview 监听端口 | `8443` | `$env:PORT="3000"; npm run dev` |
| `FIGMA_PUBLIC_URL` | 子路径部署的 base 前缀 | 无（根路径 `/`） | `FIGMA_PUBLIC_URL=/yue` → base 为 `/yue/` |
| `VITE_CONFIG_NATIVE_IGNORE_WARNING` | 抑制 `__dirname`/JSON import 警告 | 未设 | `=true` |

### 2.1 子路径部署（base）

```ts
// vite.config.ts
base: process.env.FIGMA_PUBLIC_URL ? `${process.env.FIGMA_PUBLIC_URL}/` : '/',
```

部署到非根路径（如 `https://example.com/yue/`）时：

```bash
# PowerShell
$env:FIGMA_PUBLIC_URL="/yue"; npm run build
```

构建产物的资源引用会自动加 `/yue/` 前缀。

## 三、静态托管部署

`dist/` 是纯静态目录，可托管于任意静态服务器。

### 3.1 Nginx

```nginx
server {
  listen 80;
  server_name yue.example.com;
  root /var/www/yue-frontend/dist;
  index index.html;

  # SPA 回退：未命中文件走 index.html
  location / {
    try_files $uri $uri/ /index.html;
  }

  # 音频文件缓存
  location /audio/ {
    expires 30d;
    add_header Cache-Control "public, immutable";
  }

  # 带 hash 的资源永久缓存
  location /assets/ {
    expires 1y;
    add_header Cache-Control "public, immutable";
  }
}
```

### 3.2 Vercel / Netlify

- 构建命令：`npm run build`
- 输出目录：`dist`
- 这类平台自动处理 SPA 回退，无需额外配置。

### 3.3 GitHub Pages

```bash
# 子路径部署到 https://<user>.github.io/<repo>/
$env:FIGMA_PUBLIC_URL="/<repo>"; npm run build
# 然后把 dist/ 推到 gh-pages 分支
```

### 3.4 本地快速验证

```bash
npx serve dist -l 8080
# 或
npx http-server dist -p 8080
```

## 四、Figma Make 部署

项目根目录的 `.figma/make/` 是 Figma Make 环境的配置与脚本。

### 4.1 站点配置

[`.figma/make/site.json`](file:///c:/Users/liu123/WorkBuddy/2026-09-01-20-12-50/yue-frontend/.figma/make/site.json) 定义站点元数据，构建时由 `figmaSiteConfiguration` 插件注入 `index.html`：

| 字段 | 当前值 | 作用 |
| --- | --- | --- |
| `description` | 粤语学习平台说明 | meta description、og:description |
| `robots.index` | `false` | 生成 `noindex` meta + `robots.txt` Disallow |
| `accessibility.addBypassLinks` | `false` | 是否注入「跳到主内容」无障碍链接 |
| `accessibility.ignoreReducedMotion` | `false` | 是否忽略 prefers-reduced-motion |

### 4.2 Figma Make 脚本

`.figma/make/` 下的 `dev`、`build`、`deploy`、`deploy-preview` 等是 Figma Make 运行时调用的脚本，在 Figma Make 平台内托管时自动执行。本地开发**无需手动调用**这些脚本，直接用 `npm run dev` 即可。

### 4.3 在 Figma Make 中发布

1. 在 Figma Make 平台打开本项目。
2. 平台会读取 `vite.config.ts` 的 4 个 Figma 插件（站点配置、错误重放、Refresh 兜底、Kit 预览）。
3. 触发平台 `deploy` 脚本，产物由平台托管，`FIGMA_PUBLIC_URL` 由平台自动注入。

## 五、版本与发布流程建议

### 5.1 版本号

`package.json` 的 `version` 字段。建议遵循语义化版本：

| 变更类型 | 版本 | 示例 |
| --- | --- | --- |
| 新增页面/重大功能 | major | 2.0.0 |
| 新增词条/Sheet/小功能 | minor | 1.1.0 |
| 修 bug/调样式 | patch | 1.0.1 |

### 5.2 发布检查清单

- [ ] `npm run build` 成功，`dist/` 生成
- [ ] `npm test` 全绿
- [ ] `npm run preview` 本地预览无控制台错误
- [ ] 移动端尺寸（≤430px）下 5 Tab 与抽屉正常
- [ ] 音频文件已复制到 `dist/audio/`
- [ ] 子路径部署时 `FIGMA_PUBLIC_URL` 已设置
- [ ] `package.json` 版本号已更新
- [ ] 若需被搜索引擎收录，把 `site.json` 的 `robots.index` 改为 `true`

### 5.3 回滚

纯静态部署回滚成本低：保留上一版 `dist/` 备份，覆盖即可。localStorage 数据结构向后兼容（`load()` 用展开合并补默认值），无需数据迁移。

## 六、缓存策略

| 资源 | 缓存策略 | 理由 |
| --- | --- | --- |
| `assets/index-*.js` / `*.css` | 长期（1 年，immutable） | 文件名含 hash，内容变即换名 |
| `audio/*.mp3` | 中期（30 天） | 内容稳定，但无 hash |
| `index.html` | 不缓存或短缓存 | 否则用户拿不到新版本入口 |
| `robots.txt` | 短缓存 | 轻量，可频繁更新 |

## 七、监控与可观测性（可选）

当前项目无内置监控。如需接入：

- **前端异常**：在 `src/main.tsx` 包一层 `ErrorBoundary`，上报到 Sentry/自建端。
- **行为埋点**：在 `lib/store.ts` 的各 `mark*` 函数内加埋点上报（注意 localStorage 离线场景需队列重试）。
- **性能**：用 `web-vitals` 采集 LCP/CLS/INP，在 `main.tsx` 上报。

> 接入监控时遵循 [00-开发约定](./00-开发约定.md)：只改 `yue-frontend/`，不污染其他两端。
