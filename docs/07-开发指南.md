## 一、环境搭建

### 1.1 工具链要求

| 工具 | 版本 | 来源 |
| --- | --- | --- |
| Node.js | 22 | `.mise.toml` 锁定 |
| 包管理器 | npm（项目含 `package-lock.json`） | pnpm 亦可，但供应链策略可能拦截新包，首选 npm |
| 编辑器 | VS Code / IntelliJ IDEA | 安装 ESLint / Tailwind 插件体验更佳 |

> `.mise.toml` 同时声明了 `pnpm@10.34.3`，但若 `pnpm install` 报 `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION`，改用 `npm install` 即可。

### 1.2 首次启动

```bash
cd yue-frontend
npm install                 # 安装依赖
npm run dev                  # 启动开发服务器（默认端口 8443，被占用时可设 $env:PORT="3000")
```

启动后访问终端输出的 `Local` 地址（如 `http://localhost:3000/`）。Vite 提供 HMR，改代码即时热更新。

### 1.3 常用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 启动开发服务器（`--host 0.0.0.0` 支持局域网访问） |
| `npm run build` | 生产构建，产物输出到 `dist/` |
| `npm run preview` | 预览构建产物 |
| `npm test` | 运行全部测试（一次性） |
| `npm run test:watch` | 监听模式测试 |
| `npm run format` | 用 `oxfmt` 格式化代码 |

## 二、项目结构速查

```
src/
├─ main.tsx              # 入口，挂载 <App/>
├─ App.tsx               # 根组件 + Tab 路由
├─ index.css            # 全局样式 + Tailwind + 主题令牌
├─ screens/             # 5 大页面（表现层）
├─ components/          # 复用组件 + Sheet 抽屉
├─ lib/store.ts         # 状态机 + localStorage 持久化
├─ lib/speech.ts        # 语音服务
├─ data/words.ts        # 词表 + 分类
├─ data/dictionary.ts   # 翻译词典
└─ data/audio-manifest.ts # 音频映射
```

**数据流向**：`data/`（静态数据）→ `lib/store.ts`（运行时状态 + 持久化）→ `screens/`（通过 `useLearning()` 订阅渲染）。

## 三、代码规范

### 3.1 TypeScript

- `tsconfig.json` 启用 `strict: true`，**禁止 `any`**（测试 stub 的 `@ts-expect-error` 除外）。
- 组件、函数均使用**默认导出**（页面组件）或**具名导出**（工具函数、子组件），与现有风格一致。
- 类型优先用 `interface` 描述数据结构（如 `Word`、`LearningState`），用 `type` 描述联合/工具类型（如 `SheetKind`）。

### 3.2 字符串引号

含撇号的字符串用**双引号**或转义，避免单引号断链（来自 `AGENTS.md`）：

```tsx
// ✅ 正确
<p>"We're here to help"</p>
// ❌ 错误（构建中断）
<p>'We're here to help'</p>
```

### 3.3 JSX

- 标签必须闭合、大括号必须平衡。
- Tailwind 工具类直接写在 JSX `className` 中；全局 CSS、`@font-face`、主题变量放 `src/index.css`。
- **不使用** `tailwind.config.js` 与 PostCSS 配置（Tailwind v4 通过 `@tailwindcss/vite` 接入）。

### 3.4 命名

- 文件：页面 `XxxScreen.tsx`，抽屉集合 `XxxSheets.tsx`，数据 `xxx.ts`，工具 `xxx.ts`。
- 组件：PascalCase（`SoundButton`、`StuckList`）。
- 函数/变量：camelCase。
- 常量：UPPER_SNAKE（`DAILY_GOAL`、`KEY`）。

## 四、开发工作流

### 4.1 新增一个底部 Tab 页面

以新增「设置」页为例：

1. **创建页面组件** `src/screens/SettingsScreen.tsx`，默认导出：
   ```tsx
   export default function SettingsScreen() {
     return <div className="flex flex-col h-full bg-[#f0f4ff]">...</div>;
   }
   ```
2. **在 `App.tsx` 注册**：
   ```tsx
   import SettingsScreen from "./screens/SettingsScreen";
   import { Settings } from "lucide-react"; // 选一个图标

   const tabs = [
     // ...原有 5 个
     { id: "settings", label: "设置", icon: Settings },
   ];

   // renderScreen 的 switch 增加分支
   case "settings": return <SettingsScreen />;
   ```
3. **验证**：dev 服务器热更新后底部出现新 Tab，点击切换。

> 注意：底部 5 个 Tab 是移动端惯例，新增到 6 个会挤占点击区，建议慎用；如非高频入口，改为页面内跳转或 Sheet 抽屉。

### 4.2 新增一个底部抽屉（Sheet）

以在首页新增「学习统计」抽屉为例：

1. **在 `src/components/HomeSheets.tsx` 扩展 `SheetKind` 联合类型**：
   ```ts
   export type SheetKind = null | "follow" | "practice" | "vocab" | "quiz" | "stats";
   ```
2. **在 `HomeSheet` 派发组件的 switch 增加 case**，用通用 `Sheet` 容器：
   ```tsx
   case "stats":
     return (
       <Sheet title="学习统计" onClose={() => setSheet(null)}>
         <StatsContent />
       </Sheet>
     );
   ```
3. **在页面触发入口**（如 `HomeScreen` 的 `quickModules`）加一项：
   ```tsx
   { icon: BarChart, label: "学习统计", kind: "stats" as SheetKind },
   ```
4. 复用 `SoundButton` / `WordRow` 等通用组件保持视觉一致。

### 4.3 新增词条

在 `src/data/words.ts` 的 `raw` 数组追加一项，**id 会自动生成**（`w${index+1}`）：

```ts
{ yue: "飲茶", jyut: "jam2 caa2", man: "喝早茶（粤式）", cat: "eat",
  example: "我哋去飲茶。", exampleMan: "我们去喝早茶。" },
```

> ⚠️ `Word.id` 由数组下标生成，**在数组中间插入/删除会改变后续词的 id**，导致已保存的 `learned/stuck/reviewed` 记录错位。新增词请**追加到末尾**，不要插在中间。如需稳定 id，参考 03-架构文档演进建议（改用 hash id）。

### 4.4 新增翻译词典条目

在 `src/data/dictionary.ts` 的 `rawMap` 追加三元组，**顺序无所谓**（导出时会按普通话长度降序排列，保证贪心最长匹配）：

```ts
["喝早茶", "飲茶", "jam2 caa2"],
```

### 4.5 新增离线音频

1. 把 `aXXXX.mp3` 放到 `public/audio/`（dev 时由 Vite 静态服务）和 `dist/audio/`（生产构建后）。
2. 在 `src/data/audio-manifest.ts` 增加映射：
   ```ts
   "飲茶": "/audio/a0209.mp3",
   ```
3. `speech.ts` 的 `speak("飲茶")` 会自动优先播放该离线音频，未收录则回退 TTS。

## 五、状态管理使用指南

### 5.1 读取状态

在组件中用 `useLearning()` hook 订阅状态，状态变更自动重渲染：

```tsx
import { useLearning } from "../lib/store";

export default function MyScreen() {
  const s = useLearning();
  return <p>已学 {s.learned.length} 词 · 铜板 {s.coins}</p>;
}
```

### 5.2 写入状态

调用 `lib/store.ts` 导出的动作函数，**不要直接改 `state`**：

```tsx
import { markLearned, buyItem } from "../lib/store";

markLearned("w1");              // 记粤语斩对
buyItem("道具X", 30);           // 商城购买
```

每个动作内部会：① 更新 `state` ② 写入 `localStorage` ③ 通知所有订阅组件。

### 5.3 新增状态字段

1. 在 `LearningState` interface 加字段并给默认值（`DEFAULT`）。
2. 在 `load()` 的 `{ ...DEFAULT, ...JSON.parse(raw) }` 合并逻辑保证旧数据兼容。
3. 按需新增动作函数操作该字段。

> 由于 `load()` 用展开合并，新增字段对历史用户的 localStorage 自动补默认值，无需迁移脚本。

## 六、测试编写指南

### 6.1 单元测试

放在 `src/__tests__/xxx.test.ts`，命名 `<模块名>.test.ts`。模板：

```ts
import { describe, expect, it, beforeEach } from "vitest";
import { resetAll } from "../lib/store";

describe("新模块", () => {
  beforeEach(() => {
    localStorage.clear();
    resetAll();
  });

  it("用例描述", () => {
    expect(true).toBe(true);
  });
});
```

### 6.2 系统测试

放在 `src/__tests__/Xxx.system.test.tsx`，用 `@testing-library/react` 渲染并断言 DOM：

```tsx
import { render, screen, fireEvent } from "@testing-library/react";
import MyScreen from "../screens/MyScreen";

it("点击按钮触发某行为", () => {
  render(<MyScreen />);
  fireEvent.click(screen.getByText("购买"));
  expect(screen.getByText("购买成功")).toBeInTheDocument();
});
```

### 6.3 注意事项

- 时间相关用例用 `vi.useFakeTimers()` + `vi.setSystemTime()`，`afterEach` 调 `vi.useRealTimers()`。
- `speech.ts` 的 `Audio.play()` 在 jsdom 抛 "Not implemented"，源码已 try-catch 吞掉，无需 mock。
- 失败时**改测试不改源码**（除非源码真有 bug）。

## 七、常见问题

| 问题 | 解决 |
| --- | --- |
| `Port 8443 is already in use` | 设 `$env:PORT="3000"`（PowerShell）再 `npm run dev` |
| `ERR_PNPM_MINIMUM_RELEASE_AGE_VIOLATION` | 改用 `npm install`（见 1.1） |
| 改了 `words.ts` 中间词后学习记录错乱 | 只在末尾追加，不插中间（见 4.3） |
| 新音频不播放 | 检查 `audio-manifest.ts` 映射 + 文件是否在 `public/audio/` |
| Tab 切换后页面状态丢失 | 这是 `useState` 路由的预期行为；如需保留，把状态提升到 `store.ts` |
| Tailwind 类不生效 | 确认 `src/index.css` 有 `@import 'tailwindcss';`，无需 config 文件 |
